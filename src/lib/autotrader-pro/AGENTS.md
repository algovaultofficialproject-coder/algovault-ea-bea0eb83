- Multi-timeframe SMC lives in pure smc.ts (closed-bar structure, liquidity, OB/FVG reads) and mtf.ts (top-down 1H→1M confluence tiers, thresholds from EngineSettings.mtfMode); its signals are journaled and displayed only, never auto-executed, so execution still flows through the existing gated engine.
- TP/SL lives in pure tpsl.ts (structure+ATR stops, liquidity targets capped before 30M/1H structure, TP1–TP3 management, walk-forward TP/SL backtests per market class); MTF signals and the home robot (pro-signal withTpSl: stop + TP2) both use it so every signal shares one stop/target model.
- V3 market-change detection lives in pure market-change.ts (11-regime classifier with hysteresis smoothRegimes, chop/exhaustion/divergence/squeeze/volume/session/trap/zone/correlation reads, 0–100 change score); runEngine only re-weights strategies through adaptScore when settings.adaptive is on, so detection never places orders by itself and unavailable data (volume, order flow, yields) is reported, never invented.
- Open-trade reading: in-app usePositionGuard is a read-only 1 s balance/equity/P-L loop; the 24/7 server watch and auto-closing were removed by request, so the app never closes trades (broker-side SL/TP only).
- Gemini referee: keys in server-only gemini_keys (owner edits on /bridge-keys, key 2 is fallback); one verdict per symbol per closed 15m bar cached in gemini_verdicts so phones agree; its prompt classifies the market state first and applies a per-state playbook; pure refereeAction decides keep/agree/follow; for the home robot Gemini only adds confidence when it agrees and never blocks a Pro signal; Gemini failure never blocks the engine signal.
- Strategy book lives in pure strategy-book.ts: families of 10 variants in three modes — trend families (trigger + trend-state, EMA bias with a minimum slope), range families (band fade, RSI snapback, failed-breakout trap, micro-range scalp) that only trade when no clean trend (ADX below RANGE_MAX_ADX), and transition families (range breakout, breakout retest, breakout pressure, momentum-candle break, exhaustion turn) that need no trend because the slower EMA lags a change of state — sharing one finisher (no-chase limit, structural stop, closed-candle confirmation); strategy-policy.ts orders them by role and the engine scans them as SCAN_BOOK, so the trading-app robot (pro-signal → useAutoScalp) uses the same book automatically.
- Paper/backtest trade management books 60% at 0.6R, moves the rest to break-even and trails 1 ATR (risk presets + store SETUP_RISK migration); live broker orders keep fixed SL/TP, so re-measure win rate and profit factor together before changing it.
- Every order carries one SL and one TP inside target-band.ts (engine signals clamped via bandTarget, so AutoTrader Pro Execute too); trading-app averageTarget picks the nearest structure level inside the MIN/MAX_TARGET_RR band (else DEFAULT_TARGET_RR, never past TP2); without a usable plan the engine TP is clamped to the same band.
- Home robot (trading app, every market) takes every AutoTrader Pro decision from scanProSignal directly; live-gate.ts is not applied to it, so the trading-app bots never WAIT while Pro shows a signal.
- Home robot skips new entries during a high-impact news blackout (pure newsBlackout in fundamentals.ts on the existing calendar feed); an unavailable calendar never blocks, matching 'optional data never blocks core'.
- Smart orders: pure order-planner.ts picks BUY/SELL MARKET, STOP, LIMIT, WAIT or REJECT from the executable side (ask for BUY, bid for SELL), tick-rounds and validates broker distance rules; scanner-board.ts builds rows from SymbolScan; order-book.ts holds the device-local lifecycle; pending-orders.functions.ts re-validates against the live broker quote before sending and reports "placed" only on a broker ticket, so no order is ever claimed unconfirmed.
- Trading-app relay: pure bot-relay.ts rowRelaySignal sends every BUY/SELL scanner-board signal (market, stop or limit) to the bot (manual_signals → useTurboSignals) immediately as a plain BUY/SELL, once per signal key; /autotrader runs usePortalSync so the account's bots are known.
- Breakout-role signals (isBreakout) keep their own stop behind the broken level and measured-move target, clamped to the target band, in withTpSl; the liquidity plan would cap them before the level being broken.
- Candle reading is enforced in the shared finish(): trend/transition signals are blocked by a long opposing rejection wick, and close location plus swing structure (HH/HL, LH/LL) are soft confirmations; family V (Smart Money FVG Retest) needs a structure-breaking displacement with a fair-value gap and trades only its first rejected retest, stop behind the order block, so SMC entries never chase.
- AutoTrader Pro scans only 1m, 5m and 15m (SCAN_INTERVALS); strategy-book frame sets and the MTF ladder (15M bias, 5M structure) are built from those three charts only.
- Pairs have no trading-mode choice: every pair uses the normal full AutoTrader Pro stop/target plan (scalp mode was removed by request; a stored legacy mode field is ignored).
- Momentum quality lives in pure momentum.ts (current push + next-shift probability per 1m/5m/15m, A+…C grade on each latest closed candle via withMomentum in scanProSignal; each chart has one role (TIMEFRAME_ROLE: 15m trend, 5m change, 1m timing) and pure readDirectionChange uses 1m + 5m against 15m — a confirmed change toward the signal lifts it to A, one against it steps the grade down or makes it C; unreadable frames are ignored; every grade A+…C trades, the grade only adjusts confidence — WAIT on grade removed by request). Small Account Growth (balance-based lot sizing) was removed by request; lots come from each pair's settings, capped only by the loss limit.
- Per-symbol strategy fit lives in pure symbol-fit.ts (market class → avoided strategy families, confirmed-only for fast markets) applied as proDecision's fits filter for the home robot; the loss limit (pure loss-cap.ts with its own lot-to-money helpers, device-local small-account-prefs, on by default) shrinks trades then lot so one signal's stop-out stays within the typed limit, always capped at the strict MAX_PLANNED_LOSS_ZAR ceiling with a COST_BUFFER share kept for spread/slippage, else the signal is skipped.
- No-WAIT home robot: pure direction.ts scores BUY/SELL/NO-TRADE from 1m/5m/15m evidence (15m bias, 5m confirm, 1m timing); when no strategy setup exists scanProSignal's noWait uses the score's side with the shared stop/target plan (bias-signal), and NO-TRADE is explanation only. strategy-library.ts lists book strategy × timeframe × suited market class (900+), status only from stored ProState.perf, never invented.
